# NCAA Division I women’s basketball launch plan

## Scope and launch season

Add `ncaaw` as a third sport, alongside `ncaaf` and `ncaam`. Launch with the active **2026–27** season (`year=2027`, ESPN’s season-ending-year convention). Ingest all of **2025–26** (`year=2026`) for the ranking model’s one-season lookback; publish that season as an archive only if it meets the same coverage standard. Older history, basketball player stats, changes to the composite ranking formula, and changes to the football-only game-count page are out of scope for v1.

Reuse men’s basketball ranking parameters: a 25-game SRS quota, one season of lookback, existing margin-of-victory caps, and record/SRS/SOS weights of 25/60/15. Keep inputs isolated by sport; this is one national D-I ranking with no FBS/FCS split or football preseason prior. Keep men’s and football output unchanged.

## 1. Backend foundation (`stats-go`)

- Add the `ncaaw` persistence key and register a separate ESPN client for `basketball/womens-college-basketball`. Share the basketball client behavior, not URL configuration, cached season state, identities, or result rows. Support scoreboard, conference, team listing and per-team fallback, and game summary endpoints. See [ESPN API notes](espn-api.md).
- Reuse a single-day scoreboard walk with `groups=50` for schedules and conference discovery. Keep the two-day recent-game window with Eastern dates; validate late-night and DST boundaries without changing men’s ranking semantics. Handle incomplete and canceled games the same as existing basketball. Verify the historical fallback date span against feed calendars. Determine D-I membership using the women’s conference data for the relevant season before ranking; retain real games against non-D-I opponents without ranking those opponents. The current conference-label endpoint is not historical, so audit unknown historical IDs and membership rather than silently dropping teams.
- Apply the basketball parameters and single-division paths in the ranker and updater. Register `ranker ncaaw` and `updater ncaaw` with `teams`, `season`, `games`, `ranking`, and `backfill`. Keep football-only flags and scheduling behavior unchanged. Backfill missing team metadata from the women’s per-team endpoint.
- Reuse the existing `team_names`, `team_seasons`, `games`, and `team_week_results` tables with `sport='ncaaw'`. Keep existing composite keys, `fbs=1` for D-I team seasons, `fbs=true` for D-I ranking rows, and `final_raw` as `double precision`. The ranking phase is `postseason=0` for regular snapshots and `1` for the single latest postseason/Final snapshot per season. No new tables, columns, or keys are needed. The Compose smoke test exposed GORM’s default `numeric` for `final_raw`; explicitly pin the model to the existing `double precision` contract and verify migration on fresh and populated PostgreSQL. `games.game_id` is globally unique, as assumed by dependent stat rows; normal upserts and retry placeholders must reject cross-sport event ID collisions without modifying the incumbent row.
- Update the backend architecture, usage, and ESPN docs with the implemented contract and operational caveats. Keep the PR scoped to this feature; use [multi-repo release order](multi-repo-workflow.md).

## 2. Backend rollout and backfill

- A women's weekly ranking covers completed games in the named ESPN week and earlier weeks. It ends at the Monday midnight Eastern after that week's last game. ESPN can start Week 1 with a Sunday opener before the first Monday slate; using the week's last game avoids chopping off the rest of Week 1. The latest regular result uses the same positive week key. Postseason replaces one `ncaaw` Final snapshot (`postseason=1`, `week=0`) even when ESPN omits the week. Football and men's basketball keep their window and numbering rules.
- Run `updater ncaaw backfill --from 2026 --to 2027` on staging. It uses explicit season-ending years and a daily Eastern `groups=50` walk, not the flat calendar’s incomplete game-day list. It audits both years, but publishes only 2027 by default. An explicit earlier `--publish-from` requires that season's own prior year inside the audited range; do not publish it as an archive until coverage and membership pass. No lookback outside the audited one-season window is used.
- Publish only after all requested seasons pass the game and team audit. A failure leaves existing ranking snapshots untouched; partial raw imports can remain for retry. Run only one women's import or ranking command at a time. Rerun to verify idempotence and independently reconcile totals/IDs, check records and D-I membership (the conference labels and bulk D-I list are current-only), and compare football/men's data before and after. If a stored row is stale or conflicts with a scoreboard final, investigate the mismatch and force an individual game reimport only after verifying the source.
- Enable scheduled polling before starting the frontend rollout. `updater schedule --ncaaw-polling` is off by default; Compose `NCAAW_POLLING=true` supplies the flag default. Women's games run every five minutes (two minutes after the men's tick), metadata refreshes weekly, and the season initializer retries each morning November 1–14 Eastern until membership exists. Initialization uses the expected season-ending year, not ESPN's cached current year, and the ranking worker waits for both membership and a rankable game in that season.
- Catch up missed games with the verified backfill **before enabling polling**: the poll only covers today and yesterday Eastern. Verify the opted-in scheduler on disposable PostgreSQL/Compose, then confirm in production that a women's poll imports a final and publishes a snapshot. The scheduler uses the shared site build trigger; check request rates and build frequency with both basketball sports active. Roll back by setting `NCAAW_POLLING=false` and recreating the updater, not by deleting imported data. Do not use production credentials for tests.

## 3. Frontend (`stats-web`, after the backend contract lands)

- Add `ncaaw`/`d1` to Eleventy and client sport configuration. Generate `/ncaaw/ranking/d1/<year>/<week-or-final>/` from actual published snapshots. `/ncaaw/` and the Women’s Basketball nav item should lead to the latest verified 2026–27 snapshot at launch. Add titles and sitemap entries, and update smart 404 redirects. Keep existing routes and the homepage default intact.
- Reuse ranking and team pages. Link ranking rows to `/team/<id>#ncaaw` for the women’s chart; show tabs only for sports with data. Include women’s-only teams in the team directory. Use the women’s metadata when rendering women’s ranking rows; verify multi-sport school IDs produce a single team page and do not mix results.
- Support rolling deployment: a database with no women’s rankings must still build, with no women’s nav, pages, tabs, or sitemap entries. Gate all sport enumerations that depend on women’s data, including team paths and redirects; do not swallow genuine DB errors or relax existing-sport data checks. Verify team history and non-contiguous weeks do not produce broken links.
- Run frontend lint, typecheck, tests, and full builds against seeded and unseeded fixture databases. Check a 2027 weekly route, an archived Final if published, a women’s-only team, a shared school, the empty-data case, and the existing football and men’s routes.

## Evidence and regression fixtures

Public ESPN spot checks found a flat 2025–26 calendar, D-I conference IDs from `scoreboard/conferences?groups=50`, team metadata, and usable game summaries. On 2026-01-17 the scoreboard returned 122 events with `groups=50` versus 4 unfiltered. The 2026-04-05 championship summary (`event=401856590`) marked the game as postseason but omitted `header.week`. These are sample observations, not a full coverage audit.

Add hermetic fixtures for women’s season metadata, a busy slate, a late Eastern game, a non-D-I opponent, a game with missing postseason week, a season rollover, shared school IDs across sports, and colliding event IDs. Exercise ingestion, retry, ranking output, and the static build as separate verification steps.
